# ENISHI Gift Forge — ご縁ギフト設計室

セミナーや説明会で、紹介者へのお礼ギフトを「案内文だけ」ではなく、紹介条件・同意・重複防止・履行・監査・公開承認まで含めて設計するAKATSUKI Skillです。

作成者表示: `AKATSUKI / MASA`

## 使い方

次のように依頼します。

```text
/enishi-gift-forge
7月のAI活用セミナーで、友人を1名紹介して参加した人へのお礼ギフトを設計して。
紹介先の連絡先を紹介者に入力させず、案内文・フォーム項目・重複防止・dry-run・改善点一覧まで出して。
```

短い依頼でも発火できます。

```text
紹介者へのプレゼントを設計して
紹介特典の問題点を洗い出して改善して
セミナー紹介キャンペーンを公開前レビューして
```

## 返るもの

- ギフト候補の比較と採用理由
- 紹介成立条件と状態遷移
- 紹介者・紹介先向けの案内文
- 同意、個人情報、対象外、重複、期限の設計
- 購入・発送・送信をしないdry-run
- 問題点、改善点、残リスクの一覧
- 95点ゲート用の品質レビューと公開承認パケット

## 最初に渡すと精度が上がる情報

セミナー名、開催日、対象者、紹介成立条件、ギフト候補、予算、上限、履行方法、地域、利用チャネル、公開先を入力してください。不明な値は `[TBD]` のまま扱います。

## 公開前の注意

外部公開、SNS・メール・LINE・Lark送信、ギフト購入・発送、個人情報の同期は承認前に実行しません。指定されたGrok共有URLは初版作成時点で本文を取得できなかったため、このSkillはその内容のクローンではなく、ユーザー要件からの独立設計です。

## インストール・有効化

AKATSUKIのプロジェクトSkillとして登録済みです。追加のnpm/pip依存はありません。Claude Code側の検出用mirror、`config/skills.yaml`、`.claude/skills/INDEX.md`を同時に管理します。

関連する既存Skillは必要な工程だけ呼びます。

- `lead-funnel-os`: 紹介導線・対象者・CTA・計測の上流設計
- `komainu-forge`: 外部SkillやOSSを実際に取り込む場合の安全ゲート
- `oss-japan-foundry`: ライセンス・出典・公開・派生関係の判定
- `finish-to-done`: dry-run、レビュー、テスト、差分確認、承認待ちまでの完了規律

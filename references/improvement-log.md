# 初版の問題点と改善ログ

## Before: そのまま「紹介者にプレゼント」を作る場合の問題

| ID | 問題 | リスク | 改善 |
|---|---|---|---|
| P01 | 「連れてきた」の定義がない | 対象者の判定がぶれる | 申込・同意・参加・期間・上限を状態と条件にする |
| P02 | 紹介先の連絡先を紹介者が入力する | 無断提供・迷惑連絡 | 紹介先が自分で登録する導線を第一候補にする |
| P03 | ギフトの金額・在庫・期限が未定 | 履行不能・期待値の誤り | 候補比較と `[TBD]` 管理を必須化 |
| P04 | 自己紹介・重複紹介を想定しない | 不正・二重付与 | 一意キーと重複判定を定義 |
| P05 | 紹介者へ紹介先の状況を返す | プライバシー侵害 | 最小限の受付結果だけ返す |
| P06 | 参加前に特典を確約する | キャンセル・トラブル | `eligible` 判定後に履行する |
| P07 | SNS・メールを一斉送信する | スパム・同意不備 | payload作成と承認を分離 |
| P08 | 景品・金券・金銭の扱いを確認しない | 規約・法務・税務リスク | 専門確認が必要なHard Blockにする |
| P09 | 問い合わせ・再送・代替がない | 運用停止 | 履行・失敗・問い合わせ状態を持つ |
| P10 | AIに成果・法令適合を断定させる | 誤認・信用毀損 | 事実・仮定・未確認を分離 |
| P11 | 参照元を無断クローンする | 著作権・出典・信用リスク | 本文取得不能時は独立設計として扱う |
| P12 | 公開後の修正・停止方法がない | 誤配布の拡大 | ロールバック・停止・訂正導線を公開パケットに含める |

## After: 初版Skillで追加した改善

- `SOURCE_BOUNDARY` を追加し、参照元取得不能・権利不明を明示
- `draft` から `reconciled` までの紹介状態を定義
- 紹介先が自分で登録する同意優先設計を標準化
- ギフトの原価・在庫・期限・代替・履行を比較項目化
- Offer / Experience / Operations / Risk の4レーンレビューを追加
- 95点以上かつHard Block 0件を公開条件化
- 外部送信、購入、発送、個人情報同期を承認必須化
- dry-run、監査ログ、read-back、停止・訂正の考え方を明記
- 参照元のクローンではなく、AKATSUKI内の独立設計として作成者表示を整理

## 未解決・要入力

- セミナー名、日程、主催者、対象地域
- ギフトの候補、予算、在庫、履行主体
- 紹介成立条件と紹介上限
- 利用チャネルと保管期間
- 景品・金券・税務・業界規約の確認者
- 公開先リポジトリ、アカウント、visibility、ライセンス
- 指定Grok共有URLの本文と、利用許諾・参照範囲
